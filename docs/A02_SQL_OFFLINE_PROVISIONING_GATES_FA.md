# A02 — پیش‌نیاز SQL Server برای انتقال از هلو (رسانه نصب آفلاین)

**وضعیت:** قطعه تشخیصی جدید، نه نصب‌کننده نهایی. تا زمانی که ناشر نرم‌افزار کل بسته رسمی نصب **SQL Server Express** را با نسخه و هش قابل اعتماد تأیید نکرده است، `-Mode Install` **عمداً متوقف می‌شود**. وجود این فایل به معنای توانایی نصب خودکار SQL Server نیست.

## دو اصل معماری

1. استفاده معمول Factor-easyPro با ذخیره‌سازی محلی انجام می‌شود و **به SQL Server نیاز ندارد**. پیش‌نیاز WebView2 در PR #145 از راه نصب‌کننده آفلاین Tauri/NSIS مدیریت شده است.
2. فقط برای تبدیل بکاپ اصلی هلو، موتور SQL Server سازگار لازم می‌شود. **هرگز SQL Server موجود هلو را بدون اجازه تغییر نمی‌دهیم** و نصب SQL را به همه کاربران تحمیل نمی‌کنیم.

## پیاده‌سازی فعلی

`scripts/a02-offline-sql-setup-preflight.ps1` روی Windows PowerShell 5.1 سه حالت دارد:

| حالت | نتیجه | سطح دسترسی و اثر |
|---|---|---|
| `Test` — پیش‌فرض | آزمون ساختگیِ مسیرهای غیرمجاز و فرمان‌های ایمن نصب | بدون فایل، رجیستری، SQL یا نصب |
| `Inspect` | بررسی Windows x64، فضای اولیه، عدم وجود نمونه `FINORAMIG` در رجیستری ۶۴بیتی، هش SHA-256 ثبت‌شده توسط ناشر و امضای معتبر Microsoft روی `setup.exe` | فقط خواندنی؛ بدون نصب |
| `Install` | همان پیش‌بررسی و کنترل رضایت آشکار، سپس **توقف قطعی تا فراهم‌شدن تأیید کامل رسانه و ویرایش Express** | هیچ نصبی انجام نمی‌دهد |

این کد URL دانلود، اجرای `winget`، اجرای برنامه با سطح مدیر از مسیر ناشناس، رمز `sa` یا نصب SQL در حالت استفاده معمول ندارد. آرگومان‌های نصب آینده فقط نمونه `FINORAMIG` و Windows Authentication را پیش‌بینی می‌کنند و TCP/Named Pipes را غیرفعال می‌گذارند. از نصب‌های دیگر SQL Server تغییری صورت نمی‌گیرد.

### چرا فقط امضای setup.exe کافی نیست؟

رسانه آفلاین SQL Server از فایل‌های متعددی تشکیل می‌شود؛ فایل اجرایی اصلی ممکن است امضای Microsoft داشته باشد ولی فایل‌های دیگر آسیب دیده یا جایگزین شده باشند. بنابراین برای فعال‌شدن نصب واقعی لازم است:

- نسخه و *Express edition* رسانه رسمی مشخص و حقوق توزیع توسط ناشر تأیید شود.
- یک **manifest مورد تأیید ناشر و همراه نسخه امضاشده برنامه** شامل هش همه فایل‌های بسته نصب وجود داشته باشد.
- مسیرهای فایل‌ها، اندازه، symlink/junction، تمام هش‌ها و نبود فایل اضافه کنترل شوند و درست پیش از نصب دوباره تأیید شوند.
- برنامه پیش از اجرای elevated setup، متن مجوز Microsoft را به کاربر ارائه کند؛ Windows UAC دور زده نمی‌شود.
- نتیجه نصب با کد خروج، وضعیت reboot، سرویس و نسخه SQL بررسی شود؛ قطع برق/نصب ناقص باید بازیابی و retry ایمن داشته باشد.
- Restore واقعی باید پس از نصب موفق، در نمونه اختصاصی و با کنترل نسخه بکاپ، محدودیت Express، فضای دیسک و رضایت جداگانه باشد.
- کنترل سقف Express باید بر اساس نسخه موتور انجام شود: SQL Server 2022 و قبل از آن ۱۰GB برای مجموع فایل‌های داده؛ SQL Server 2025 (17.x) برابر ۵۰GB. اندازه فایل‌های داده از `RESTORE FILELISTONLY` خوانده می‌شود؛ فایل‌های log در سقف داده حساب نمی‌شوند ولی فضای دیسک مستقل لازم دارند. نسخه Express ناشناخته در آینده تا تأیید رسمی مسدود می‌ماند.

**هیچ رسانه رسمی SQL Express یا هش مرجع هنوز به این مخزن افزوده نشده است.** تولیدکننده نباید هش ناشناخته یا لینک ساختگی در مستندات/کد قرار دهد. در CI تنها Test اجرا می‌شود و هیچ نصب SQL Server واقعی رخ نمی‌دهد.

## آزمایش مکمل موتور واقعی SQL با اطلاعات کاملاً ساختگی

اسکریپت `scripts/a02-synthetic-sql-localdb-restore-smoke.ps1` در محیط Windows CI، در صورتی که SQL Server LocalDB از قبل موجود باشد، یک **نمونه تصادفی و مجزا** از LocalDB می‌سازد و فقط روی داده مصنوعی، دیتابیس، دو رکورد ساختگی، `BACKUP DATABASE`، `RESTORE HEADERONLY`، `FILELISTONLY`، `VERIFYONLY`، `RESTORE DATABASE ... WITH MOVE` و `DBCC CHECKDB` را واقعاً اجرا می‌کند. سپس شمار و جمع مبلغ مصنوعی را کنترل می‌کند و به پاکسازی نمونه و فایل‌های آزمایش می‌پردازد.

- این آزمایش با موتور SQL واقعی انجام می‌شود، نه صرفاً mock؛ ولی **هیچ بکاپ هلو یا داده واقعی کاربر** را باز نمی‌کند.
- اگر LocalDB روی runner موجود نباشد یا حتی یک مرحله اجرا شکست بخورد، آزمون **نباید به‌عنوان موفقیت** گزارش شود.
- عبور از این آزمون فقط صحت مسیر پایه SQL را برای یک **پایگاه داده ساختگی سازگار** ثابت می‌کند؛ پشتیبانی از نسخه/ساختار/اندازه بکاپ اصلی هلو، نصب SQL Express، محیط بدون اینترنت، نگاشت اسناد و موجودی را ثابت نمی‌کند.
- بدون نتیجه سبز CI روی SHA نهایی، این بخش هنوز `NOT_VERIFIED` است.

## مراحل زنجیره مهاجرت

پیش‌نیاز SQL → انتخاب فایل ZIP → بررسی CRC و ذخیره کپی محلی (PR #150) → بررسی `HEADERONLY/FILELISTONLY/VERIFYONLY` (PR #147) → Restore در نام و مسیر جدید (PR #149) → استخراج و نگاشت نسخه واقعی جداول → تطبیق اسناد و مانده‌ها → تأیید حسابدار مستقل → commit امن.

**گیت A02 همچنان بسته است**. این کار جایگزین آزمون بکاپ واقعی در رایانه خصوصی، بررسی C1/C2/C3 و تست نصب نسخه قابل انتشار نیست. تمام PRها در حالت پیش‌نویس باقی می‌مانند.
