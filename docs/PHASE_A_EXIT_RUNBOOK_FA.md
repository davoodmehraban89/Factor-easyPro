# راهنمای خروج کنترل‌شده از فاز A — Factor-easyPro

**مبنای نسخه عمومی:** `v2.0.3`، برنامه دسکتاپ Tauri/WebView2 و IndexedDB.  
**وضعیت:** فاز A باز است. `docs/PHASE_A_RELEASE_ACCEPTANCE.json` مرجع ماشینی پذیرش است؛ هر شناسه تا زمان جمع‌آوری شواهد آزمون و بررسی مستقل باید `accepted: false` بماند.

## شیوه اجرای الزامی

1. هر اصلاح مؤثر بر محصول در شاخه مجزا و PR دارای شناسه A01..A08 انجام شود.
2. `PR Quality Gates — accounting, Windows and packaging` باید آزمون Node، ساخت Vite، ممیزی وابستگی‌ها و بسته پیش‌نمایش ویندوز را کامل و موفق گزارش کند.
3. `Phase A Windows VM Native Installer and Upgrade Lab` باید روی Windows Runner واقعی، NSIS عمومی 2.0.3 را با SHA-256 معتبر نصب و اجرا کند، داده *مصنوعی* بسازد، به کاندید **غیرعمومی** ارتقا دهد، ورود و مهاجرت v6→v7 و DPAPI را بررسی کند و نصب تازه، بازیابی و WebView2 را بیازماید.
4. برای تغییراتی که به رابط یا عملیات مالی مربوط‌اند، شواهد واقعی E2E روی نصب Tauri/WebView2 و مسیر خطای منفی لازم است؛ عبور تست Node به‌تنهایی به معنای پذیرش نیست.
5. تغییر schema یا مهاجرت دارای ریسک مالی فقط با snapshot نسخه‌دار، rollback، سنجش company isolation و ثبت تفاوت مانده‌ها قابل بررسی است.
6. پیش از هر ادغام: وضعیت دقیق SHA، فایل‌های تغییرکرده و **موفق‌بودن هر دو Workflow همان SHA** کنترل شود. هیچ Release عمومی خودکار ایجاد نشود.

## کارهای نیازمند ورودی یا تأیید بیرونی

- **کلید تجاری A06:** مالک محصول باید کلید عمومی را از فرایند امن صدور کلید خصوصیِ خارج از مخزن تحویل بدهد و سیاست چرخه عمر امضا، ابطال و پشتیبانی را تصویب کند. هرگز کلید خصوصی را برای برنامه یا GitHub Actions ارسال نکنید.
- **QA مالی:** یک حسابدار مستقل باید سناریوهای افتتاحیه، مرجوعی جزئی/کامل، چک وصول/برگشت، بستن دوره، تسویه و گزارش تراز را با داده نماینده تأیید کند؛ تصمیم/امضای پذیرش قابل جعل نیست.
- **داده قدیمی یا مشتری:** پیش از دریافت هر فایل، رضایت و شیوه ناشناس‌سازی مشخص شود. بازیابی فقط در نسخه آزمایشی جدا و با پیش‌پشتیبان انجام شود؛ داده زنده بدون دستور صریح تغییر نکند.
- **چاپ و سخت‌افزار:** چاپ واقعی A4/رسید روی چاپگر نماینده و تنظیمات ویندوز/فونت بررسی شود؛ اسکرین‌شات WebView2 جای تست سخت‌افزار را نمی‌گیرد.
- **Crash/Power:** آزمایش حذف برق یا کشتن فرایند فقط روی VM/تصویر قابل برگشت و fixture مصنوعی مجاز است؛ نتیجه برق واقعی از kill ساده استنباط نشود.

## ممنوعیت اعلام خروج از فاز A

حتی اگر همه تست‌های خودکار سبز باشند، **تا وقتی تمام گیت‌های Manifest با شاهد قابل راستی‌آزمایی پذیرفته نشده‌اند، «فاز A تکمیل شد»، انتشار تجاری یا سازگاری با همه داده‌های قدیمی اعلام نشود.** خروجی جزئی با شواهد روشن ارزشمند است ولی جای امضای QA مستقل، تجهیزات واقعی و کلید تجاری را نمی‌گیرد.
