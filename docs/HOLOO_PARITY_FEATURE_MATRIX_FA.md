# ماتریس پوشش قابلیت‌های Holoo برای Factor-easyPro

**مبنای شواهد:** schema و stored procedureهای دیتابیس Holoo1، فایل‌های راهنما و نصب موجود در محیط مرجع.  
**احتیاط:** نام جدول/رویه فقط وجود یک حوزه داده/منطق را نشان می‌دهد؛ تکمیل رفتار UI یا صحت آن هنوز با آزمون end-to-end اثبات نشده است.

## ترتیب ساخت پیشنهادی

1. **P0 — صحت مالی و داده:** relational backend، چندشرکتی، دفتر کل، اشخاص، کالا، انبار، فاکتور، خزانه/چک، backup/restore، مهاجرت و audit.
2. **P1 — عملیات روزانه:** POS، چند صندوق، بارکد، چند انبار، قیمت‌گذاری، سفارش و چاپ.
3. **P2 — عمودی‌های کسب‌وکار:** تولید، پخش، قرارداد، ضمانت و تعمیر.
4. **P3 — افزونه‌ها:** رستوران، طلا، پیامک، موبایل و اتصال مالیاتی رسمی.

**شرط:** هر ماژول فقط با سناریوی واقعی، آزمون محاسباتی، تست شکست/rollback و تطبیق سند/موجودی تکمیل اعلام شود؛ وجود صفحه یا جدول به معنی تکمیل نیست.

## ممیزی فنی Runtime و Schema

شواهد دقیق نسخه نصب‌شده، شمارش اشیا، کلیدهای اصلی، وابستگی‌های ایستا، اسکریپت‌های نسخه و مقایسه ساختاری `Holoo1` با `Holoo1_FACTORLAB_20261110` در [گزارش ممیزی Runtime و Schema](audits/HOLOO_RUNTIME_SCHEMA_AUDIT_20261111_FA.md) و فایل‌های CSV همان پوشه ثبت شده‌اند. این شواهد، ورودی تحلیل و طراحی آزمون parity هستند و به‌تنهایی تکمیل هیچ قابلیت را ثابت نمی‌کنند.
