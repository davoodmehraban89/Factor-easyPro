# A02 — آماده‌سازی امن و خصوصی بکاپ ZIP هلو روی ویندوز

**دامنه این PR:** تبدیل یک آرشیو ZIP تک‌فایلی هلو به یک **کپی محلی .bak** با تأیید CRC-32 و سرآیند `TAPE` برای بررسی بعدی SQL Server. هیچ SQL Server نصب یا متصل نمی‌شود، دیتابیس Restore نمی‌شود و هیچ رکورد حسابداری جابه‌جا نمی‌شود.

## دلیل نیاز

بکاپ ارائه‌شده توسط مالک یک ZIP با **یک فایل فشرده شامل بکاپ SQL Server** است. ابزارهای SQL فقط پس از استخراج امن کپی، با فایل باینری backup کار می‌کنند. نباید به کاربر غیرمتخصص توصیه کنیم ZIP را در محل نامطمئن باز کند یا آن را در CI عمومی بارگذاری کند.

## سه حالت مستقل

| حالت | رفتار | اثر |
|---|---|---|
| `Test` (پیش‌فرض) | روی یک ZIP کوچک و **کاملاً ساختگی** در پوشه موقت، Probe، Stage، عدم بازنویسی و رد ورودی نامعتبر را آزمون می‌کند؛ فایل‌های تست در پایان حذف می‌شوند | بدون دسترسی به بکاپ مالک، بدون اتصال SQL |
| `Probe` | فقط ساختار مرکزی/محلی ZIP را می‌خواند؛ تک‌ورودی، بدون رمزگذاری، بدون ZIP64، `stored/deflate`، طول‌ها و نام بی‌خطر | فقط خواندنی؛ CRC و نوع بکاپ SQL هنوز تأیید نشده |
| `Stage` | پس از **عبارت رضایت صریح**، فایل داخلی را به نام خنثی داخل یک پوشه با شناسه یکتا در `%LOCALAPPDATA%\FactorEasyPro\HolooMigrationStaging\...` می‌نویسد، CRC-32 را تطبیق می‌دهد و چهار بایت آغازین `TAPE` را تأیید می‌کند | **یک کپی خصوصی** می‌سازد؛ فایل اصلی را دست‌نخورده نگه می‌دارد |

بسته فقط در صورت تک‌ورودی‌بودن، عدم رمزگذاری، عدم ZIP64، حجم آرشیو حداکثر ۲ GiB، حجم داخلی حداکثر تقریباً ۴ GiB و ضریب فشرده‌سازی حداکثر ۱۰۰۰ پذیرفته می‌شود. نام فایل داخلی نمی‌تواند شامل traversal، مسیر شبکه‌ای، درایو، separator یا کنترل‌کاراکتر باشد؛ همه مقصدها با نام ثابت و تصادفی ساخته می‌شوند. لینک‌ها و junctionها در مسیر ورودی یا پوشه مقصد رد می‌شوند. هنگام استخراج، هندل فایل مبدا تا پایان عملیات برای نوشتن دیگران بسته می‌ماند؛ کپی مقصد با `CreateNew` ساخته می‌شود و فایل موجود هرگز جایگزین نمی‌شود.

**هشدار امنیتی:** تأیید ZIP CRC و چهار بایت `TAPE` فقط اثبات محدودی از بسته و *ظاهر نوع فایل* است؛ تضمین صحت SQL Server backup، محرمانگی خود فایل، قابل‌بازیابی‌بودن، اصالت تولیدکننده هلو، صحت اسناد، تراز آزمایشی یا امکان مهاجرت نیست. فایل استخراج‌شده داده مالی **بدون رمزگذاری** است: فقط در پوشه خصوصی با دسترسی محدود نگهداری شود و پس از اتمام عملیات معتبر و طبق سیاست نگهداری داده پاکسازی شود. فعلاً این ابزار به UI عمومی متصل نیست.

## اجرای فنی (Windows PowerShell 5.1)

```powershell
# آزمایش ساختگی و بدون تماس با داده خصوصی
powershell.exe -NoProfile -NonInteractive -File .\scripts\a02-private-holoo-zip-staging.ps1 -Mode Test

# فقط شناسایی بسته، بدون استخراج
powershell.exe -NoProfile -NonInteractive -File .\scripts\a02-private-holoo-zip-staging.ps1 -Mode Probe -SourceZip 'D:\Private\backup.zip'

# استخراج کپی خصوصی با تأیید صریح
powershell.exe -NoProfile -NonInteractive -File .\scripts\a02-private-holoo-zip-staging.ps1 -Mode Stage -SourceZip 'D:\Private\backup.zip' -ConsentPhrase 'I_AUTHORIZE_PRIVATE_HOLOO_STAGING'
```

مسیرهای فوق فرضی‌اند. خروجی Stage فقط **روی رایانه مالک** شامل مسیر فایل کپی‌شده است؛ این خروجی و محتوای فایل نباید به GitHub، CI، سرور عمومی یا لاگ‌های پشتیبانی منتقل شود. پوشه داخل `LOCALAPPDATA` ممکن است برای سرویس SQL Server قابل‌خواندن نباشد. تغییر ACL/انتقال به پوشه اختصاصی سرویس باید توسط نصب‌کننده آینده، به‌صورت کنترل‌شده و با کمترین سطح دسترسی انجام شود؛ هرگز ACL عمومی `Everyone` داده نشود.

## معیارهای آزمون و پذیرش

- در CI ویندوز، `-Mode Test` روی Windows PowerShell 5.1 با **فایل مصنوعی** اجرا می‌شود و باید CRC/امضای TAPE، رد بازنویسی مقصد، رد ZIP بدون TAPE و ZIP چندورودی را تأیید کند.
- بکاپ واقعی مالک فقط در محیط خصوصی بررسی شود؛ از چاپ نام ورودی، نام جداول و هش مربوط به داده واقعی در خروجی عمومی جلوگیری شود.
- ادامه زنجیره: `Stage → SQL HEADERONLY/FILELISTONLY/VERIFYONLY → Restore در دیتابیس مجزا → schema-version mapping → reconciliation → تأیید حسابدار → commit محافظت‌شده`.
- تا زمان تکمیل همه این مراحل و سه بازبینی مستقل، گیت A02 **ناموفق/باز** می‌ماند. این PR انتشار نرم‌افزار یا مهاجرت داده را فعال نمی‌کند.
