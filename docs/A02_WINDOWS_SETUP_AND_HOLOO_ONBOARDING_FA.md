# نصب آسان ویندوز و مسیر بازیابی بکاپ هلو — A02

**وضعیت در این PR:** «نصب آفلاین WebView2 + تشخیص اولیه ZIP»؛ **نه نصب SQL Server، نه Restore، نه Import**. تا زمان پذیرش مستقل و آزمون واقعی ویندوز/بکاپ، وضعیت A02 باید `accepted: false` بماند.

## دو مسیر مستقل

### استفاده عادی از Factor-easyPro
- هسته کنونی مبتنی بر Tauri/WebView2 و ذخیره‌سازی محلی IndexedDB است؛ **SQL Server برای کار روزمره نرم‌افزار پیش‌نیاز نیست**.
- سازنده NSIS، به کمک تنظیم `bundle.windows.webviewInstallMode.type = offlineInstaller`، بسته WebView2 Runtime رسمی را همراه نصب‌کننده جاسازی می‌کند. خود Tauri تشخیص موجود بودن runtime و نصب در صورت نیاز را انجام می‌دهد.
- نتیجه: نصب اصلی **بدون اینترنت برای WebView2** قابل انجام است، ولی بسته خروجی نسبت به روش `downloadBootstrapper` بزرگ‌تر می‌شود (بر اساس مستندات Tauri حدود ۱۲۷ مگابایت).
- هرگونه نیاز ارتقای سطح دسترسی استاندارد Windows/UAC همچنان معتبر است. فایل امضاشده انتشار، آزمون ماشین تمیز و نصب ارتقایی باید جداگانه تأیید شوند.

### مهاجرت از هلو (کار اختیاری)
1. کاربر مدیر، در «تنظیمات > آماده‌سازی انتقال از هلو»، فایل ZIP شخصی را فقط در همان دستگاه انتخاب می‌کند.
2. `HolooBackupProbe.mjs` با خواندن **فقط سرآیندهای محدود ZIP** وجود یک entry، نوع فشرده‌سازی و ناسازگاری/رمزگذاری را بررسی می‌کند. در حال حاضر فقط envelope را تأیید می‌کند؛ CRC، بکاپ SQL، نسخه پایگاه داده، Restore و مانده‌ها را تأیید نمی‌کند. این ابزار به هیچ پرونده‌ای نمی‌نویسد و چیزی را به سرور منتقل نمی‌کند.
3. مرحله انجام‌شده (تشخیص فقط‌خواندنی): از بخش تنظیمات، مدیر می‌تواند «بررسی پیش‌نیازهای رایانه برای انتقال از هلو» را اجرا کند. فرمان بومی Tauri (`migration_system_readiness`) بدون پوسته/اسکریپت خارجی از رجیستری ویندوز، شمار نمونه‌های ثبت‌شده SQL Server و نسخه‌های LocalDB را **فقط به‌عنوان نشانه وجود** می‌خواند و فضای آزاد درایو `%LOCALAPPDATA%` را از Win32 API گزارش می‌دهد. نتیجه هیچ داده‌ای را تغییر نمی‌دهد و همیشه `sqlCompatibilityVerified=false` و `canImport=false` است؛ اگر رجیستری قابل خواندن نباشد «نامشخص» نمایش داده می‌شود.
4. مرحله آتی: تشخیص واقعی **نسخه سازگار** SQL Server/LocalDB، بررسی Windows x64، فضای دیسک موردنیاز برای این بکاپ خاص و سلامت/اعتبار بکاپ؛ نصب فقط در صورت **نیاز واقعی، رضایت EULA مایکروسافت و درخواست روشن کاربر**، با باینری رسمی امضاشده/هش قابل‌اعتماد، بدون وابستگی شکننده به URLهای WinGet.
5. مرحله آتی: از ZIP یک **کپی** خارج شود، `RESTORE HEADERONLY`، `FILELISTONLY`، `VERIFYONLY` و بررسی نسخه انجام شود؛ با نام تصادفی مجزا و مسیرهای امن restore شود. **هرگز روی master، پایگاه داده هلو، یا دیتابیس موجود `WITH REPLACE` اجرا نشود**. SQL Server TCP/remote access به‌صورت پیش‌فرض فعال نشود.
6. مرحله آتی: schema-only inventory، آداپتور versioned برای جداول واقعی، نگاشت ریال/تومان و تاریخ/وضعیت، کنترل دوبل حسابداری و مغایرت‌های چک/بانک، ورود آزمایشی با rollback و سرانجام تأیید صاحب‌داده و حسابدار مستقل پیش از commit.

## حدود امنیت و آزمون

- اطلاعات خصوصی هلو و فایل خام، CRC/hash معرفِ نسخه واقعی، نام اشخاص/اسناد، شناسه‌ها و فایل بازیابی SQL Server نباید وارد GitHub عمومی، CI یا گزارش لاگ شوند. فقط fixtures ساختگی.
- محدودیت پروب فعلی: ZIP تک‌ورودی، حداکثر ۲ گیگابایت فایل ZIP، با یک نام UTF-8 امن، روش‌های store/deflate، بدون رمزگذاری؛ رفتار در قالب‌های دیگر **fail closed** است.
- تست‌های Node با ZIP ساختگی باید مسیر سالم، ZIP رمزگذاری‌شده، چندفایلی، خراب، بزرگ و نام ناامن را پوشش دهند. ZIP واقعی داده‌شده توسط صاحب‌داده صرفاً **در محیط محلی و خصوصی** آزموده می‌شود.
- روی PR ویندوز، NSIS واقعی و ارتقای نسخه پیشین به نسخه نامزد، با سناریوی عدم نصب SQL باید بدون تخریب داده کار کند.
- **قبل از ادعای «واردکردن بکاپ هلو»**: تست Restore واقعیِ مجاز + schema verified + reconciliation + rollback + smoke ویندوز و سه تأیید مستقل لازم است.
