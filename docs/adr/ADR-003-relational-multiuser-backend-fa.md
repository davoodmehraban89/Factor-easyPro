# ADR-003 — تغییر معماری Factor-easyPro به هسته رابطه‌ای چندکاربره

**وضعیت:** پیشنهادی؛ پیاده‌سازی backend تا تثبیت مدل استقرار و تأیید مالک محصول شروع نمی‌شود.  
**تاریخ:** 2026-11-10  
**شاخه کاری:** `work/holoo-parity-20261110`  
**هدف محصول:** جایگزین مستقل و قابل توسعه برای گردش‌های اصلی هلو، نه صرفاً ابزار مهاجرت یا گزارش‌گیری.

## مسئله‌ای که شواهد ثابت کردند

نسخه 2.0.3 فعلی Tauri 2 + Vite + IndexedDB است. مستندات A02 صریحاً می‌گویند SQL Server برای استفاده روزمره لازم نیست و فعلاً نصب SQL Server، restore بکاپ هلو و import انجام نمی‌شود. بنابراین بزرگ‌کردن installer فعلی بدون تغییر معماری، محصول را به هلو تبدیل نمی‌کند.

هلو نصب‌شده در محیط مرجع از SQL Server 2008 R2 Express استفاده می‌کند و شواهد آن شامل دیتابیس‌های عملیاتی، اسکریپت‌های نسخه‌بندی‌شده و DBTools است. SQL Server 2008 R2 فقط یک محیط legacy برای سازگاری و مهاجرت است؛ نباید موتور پیش‌فرض نصب تازه محصول باشد.

## فرض موقت استقرار

تا زمان تأیید خلاف آن، «مثل هلو» به معنی **چند کاربر هم‌زمان روی شبکه محلی (LAN)، با یک دیتابیس مرکزی روی رایانه میزبان** در نظر گرفته می‌شود. یک نصب تک‌دستگاهی می‌تواند هم‌زمان نقش Host و Client را داشته باشد.

## تصمیم پیشنهادی

1. منبع حقیقت مالی از IndexedDB به یک موتور رابطه‌ای server-grade منتقل شود. IndexedDB می‌تواند فقط cache یا draft غیرقطعی باشد؛ هیچ سند قطعی، مانده، گردش انبار یا وضعیت چک نباید فقط در مرورگر ذخیره شود.
2. گزینه اول برای spike فنی، SQL Server Express از نسخه‌ای است که در زمان انتشار رسمی، پشتیبانی و شرایط توزیع آن تأیید شده باشد. نسخه دقیق، edition، media و مجوز توزیع پیش از فعال‌سازی installer تثبیت می‌شوند. PostgreSQL فقط در صورت مزیت روشن فنی/هزینه‌ای به‌عنوان گزینه مقایسه باقی می‌ماند.
3. backend دسترسی به DB از طریق لایه native امن Tauri/Rust یا سرویس محلی کنترل‌شده انجام شود؛ UI نباید credential یا اتصال مستقیم دیتابیس را مدیریت کند.
4. مدل مالی جدید مستقل از schema هلو طراحی شود. داده هلو از طریق adapter نسخه‌دار به مدل میانی تبدیل شود؛ stored procedureها و جدول‌های اختصاصی هلو عیناً هسته محصول نمی‌شوند.
5. واحد پایه مبلغ ریال و نوع داده دقیق integer/DECIMAL باشد؛ استفاده از float برای مبلغ مالی ممنوع. تبدیل تومان/ریال باید صریح، نسخه‌دار و قابل ممیزی باشد.
6. هر عملیات مالی در یک transaction اتمی شامل سند، گردش موجودی، خزانه، ممیزی و کلید idempotency ذخیره شود.
7. پشتیبانی از چند شرکت، نقش/مجوز، audit، backup/restore و migration جزو قرارداد هسته‌اند، نه قابلیت‌های تزئینی.

## مدل نصب

### Host / Server
- بررسی وجود موتور سازگار و ظرفیت دیسک؛ نصب SQL Express فقط با رسانه رسمی امضاشده، manifest هش مورد تأیید ناشر، نمایش EULA و رضایت صریح.
- نصب در instance مجزای FactorEasyPro؛ هرگز upgrade/overwrite نمونه TNC یا دیتابیس هلو انجام نشود.
- پیکربندی شبکه فقط در صورت انتخاب LAN؛ حداقل سطح دسترسی، firewall برای شبکه خصوصی، TLS و بدون فعال‌سازی عمومی TCP.
- ایجاد دیتابیس خالی با schema migrationهای نسخه‌دار؛ ساخت کاربر سرویس با کمترین مجوز.
- backup زمان‌بندی‌شده، health check، restore drill و rollback نسخه.

### Client / Workstation
- نصب برنامه و runtimeهای رسمی مورد نیاز؛ بدون نصب موتور SQL روی هر کلاینت.
- اتصال به Host با نام/آدرس و احراز هویت کنترل‌شده.
- در صورت قطع اینترنت، شبکه داخلی و کار روزمره باید ادامه یابد؛ قطع Host باید پیام و بازیابی روشن داشته باشد.

## مسیر مهاجرت هلو

1. نگهداری فایل اصلی و restore فقط روی clone.
2. شناسایی نسخه و backup set با HEADERONLY/FILELISTONLY/VERIFYONLY و DBCC CHECKDB پس از restore.
3. اجرای/تحلیل مسیر ارتقای DBTools فقط در clone؛ احترام به شمارنده‌های Run_TableScript_Count و Run_ViewScript_Count و markerهای GO_NO.
4. استخراج schema و data inventory خصوصی، بدون انتقال مستقیم procedureهای هلو.
5. تبدیل اشخاص، کالا، انبار، فاکتورها، اسناد، چک و خزانه به مدل میانی versioned.
6. dry-run با گزارش تعداد/جمع، ردیف‌های یتیم و مغایرت‌ها؛ هیچ commit تا تأیید مالک و حسابدار مستقل.
7. تطبیق تراز کل، مانده اشخاص، موجودی و بهای کالا، وضعیت چک و اسناد پرداخت/دریافت قبل و بعد.
8. commit در یک تراکنش کنترل‌شده و امکان rollback کامل.

## چرا installer دو مگابایتی کافی نیست؟

حجم installer معیار کامل‌بودن نیست. بسته نهایی باید برنامه، runtime رسمی، نقش Host/Client، provisioning دیتابیس، schema migration، backup/restore، چاپ و منابع جانبی را پوشش دهد. حجم دقیق از dependencyهای واقعی به‌دست می‌آید؛ نه با هدف‌گذاری مصنوعی روی 2GB. همچنین فایل نصب 2GB بدون قابلیت عملیاتی و آزمون پذیرش، صرفاً بسته‌ای بزرگ‌تر است.

## گیت‌های پذیرش اجباری

- نصب تازه Host روی Windows پاک و نصب Client روی دستگاه دوم.
- اتصال دو Client و ثبت هم‌زمان عملیات با کنترل race condition و idempotency.
- آزمون قطع برنامه/سرویس/شبکه، rollback و بازیابی backup.
- خرید → ورود انبار → فروش → دریافت/پرداخت → مرجوعی → سند معکوس → تراز.
- کنترل trial balance، دفاتر معین/تفصیلی، مانده اشخاص، کاردکس و ارزش موجودی.
- چاپ RTL واقعی روی چاپگر/خروجی PDF چندصفحه‌ای.
- ارتقای نسخه قبلی بدون از دست‌رفتن داده و rollback نصب/مهاجرت.
- تأیید مستقل حسابدار برای سناریوهای نماینده.

## ریسک‌ها و محدودیت‌ها

- SQL Server 2008 R2 در نصب تازه استفاده نمی‌شود؛ فقط برای بازیابی/تبدیل داده legacy در محیط خصوصی.
- SQL Express سقف edition و محدودیت عملیاتی دارد؛ ظرفیت مشتری باید پیش از انتخاب edition اندازه‌گیری شود.
- هیچ binary، DLL، icon، font، SQL script یا کد اختصاصی Holoo در installer Factor-easyPro بسته‌بندی نمی‌شود.
- اسکریپت‌های T_Scrp.sql و SV_Scrp.sql بدون منطق DBTools و baseline معتبر اجرا نمی‌شوند؛ اجرای مستقیم ممنوع است.
- تغییر معماری از IndexedDB به backend رابطه‌ای یک migration بزرگ است و نباید با patch سطحی یا یک installer جدید وانمود شود که تمام شده است.

## پرسش باز مالک محصول

فرض چندکاربره LAN در این ADR فعال است. اگر نسخه نهایی قرار است فقط تک‌دستگاهی باشد، انتخاب موتور و مدل استقرار باید پیش از شروع backend دوباره بررسی شود.

## الحاقیه شواهد — 2026-11-11

ممیزی فقط‌خواندنی محیط مرجع و مقایسه دقیق `Holoo1` با `Holoo1_FACTORLAB_20261110` در [گزارش ممیزی Runtime و Schema](../audits/HOLOO_RUNTIME_SCHEMA_AUDIT_20261111_FA.md) ثبت شد.

- مقایسه ساختاری ستون‌ها، تعریف 240 ماژول، 440 ردیف مشخصات ستون ایندکس و 1,127 Constraint متصل به جدول، اختلافی نشان نداد.
- markerهای `Run_TableScript_Count=537` و `Run_ViewScript_Count=474` در هر دو دیتابیس با `MAX_GO_NO` فایل‌های `T_Scrp.sql` و `SV_Scrp.sql` منطبق‌اند.
- این شواهد فقط همسانی ساختاری/نقطه checkpoint گزارش‌شده را پشتیبانی می‌کنند؛ برابری داده‌های عملیاتی، سلامت کامل دیتابیس، موفقیت rollback یا parity رفتاری را ثابت نمی‌کنند.
- هیچ migration، restore، DDL، DML یا اجرای DBTools انجام نشده است.

این الحاقیه تصمیم معماری ADR را تغییر نمی‌دهد؛ صرفاً شواهد محیط legacy و آزمایشگاه را دقیق‌تر می‌کند.
