# آزمایشگاه خودکار واقعی ویندوز — Factor-easyPro

آخرین آزمون مستند: 2026-10-16  
وضعیت: **عملیاتی برای نصب و اجرای NSIS در Windows VM**؛ نه تأیید کامل انتشار عمومی.

## محیط و اجرای مجدد

- GitHub Actions، ماشین موقت `windows-latest`، Node.js 22، Rust stable و Tauri 2.
- گردش‌کار: [`.github/workflows/windows-vm-native-lab.yml`](../.github/workflows/windows-vm-native-lab.yml).
- اجرای دستی: مخزن GitHub → **Actions** → **Phase A Windows VM Native Installer and Upgrade Lab** → **Run workflow** و انتخاب `main`.
- روی PRهای تغییر‌دهنده `src/`، `src-tauri/`، `package.json`، `package-lock.json`، `vendor/`، `index.html` و فایل‌های آزمایشگاه به‌صورت خودکار اجرا می‌شود.
- کاندید نصب فقط در محیط CI با افزایش موقت شماره نسخه تولید می‌شود. فایل نسخه کاندید **به‌عنوان Release عمومی منتشر نمی‌شود**.

## مراحل آزمون واقعی

۱. اجرای تست‌های واحد/یکپارچگی و ساخت نصب‌کننده بومی `x64 NSIS` از سورس فعلی.  
۲. دریافت نصب‌کننده عمومی `v2.0.3` و تطبیق SHA-256 آن با فایل منتشرشده.  
۳. نصب واقعی `NSIS`، اجرای `app.exe` روی ماشین ویندوز و اتصال به **WebView2 برنامه نصب‌شده** از طریق CDP.  
۴. تعریف رمز مدیرِ کاملاً آزمایشی و ذخیره رکوردهای ساختگی فاکتور و کالا در IndexedDB نسخه ۶.  
۵. نصب کاندید جدید روی همان نصب قبلی؛ ورود با همان رمز و بررسی مهاجرت نسخه ۶ به ۷ با حفظ کالا و فاکتور.  
۶. نصب جداگانه و تازه کاندید در مسیر مجزا؛ کنترل ورود اولیه و Windows DPAPI.  
۷. در برنامه نصب‌شده تازه: ساخت دوره مالی، ایجاد کدینگ، فعال‌سازی یکپارچگی مالی، تعریف انبار، خرید، فروش با پرداخت جزئی، ثبت در دفتر و انبار.  
۸. خروجی و بازیابی بخشی از یک Snapshot؛ اطمینان از عدم خروج اطلاعات مشتق‌شده رمز و رد اتمی بازیابی فاکتور دستکاری‌شده.  
۹. باز کردن تنظیمات چاپ، کنترل قالب‌ها و راست‌به‌چپ بودن رابط (بدون ادعای چاپ فیزیکی).  
۱۰. حذف نسخه نصب‌شده در محیط موقت و بارگذاری گزارش‌های JSON حتی در صورت شکست.

## نقص آشکارشده در نسخه منتشرشده قبلی

نصب‌کننده عمومی `v2.0.3`، با وجود نام و مشخصات بسته `2.0.3`، برچسب نسخه `1.1.1` را در `FINORA.version` نشان می‌دهد. در تگ `v2.0.3` فایل `src/main.js` همین رشته را ثابت نگه داشته بود. در کاندید جدید، نسخه از `package.json` خوانده می‌شود و آزمونِ مطابقت نسخه موفق شده است. نقص برچسب نسخه قدیمی، مانع تست واقعی حفظ داده‌های آن نشد.

## پوشش‌نداده‌ها و گیت‌های انتشار

این آزمایشگاه با داده ساختگی و ویندوز موقت اجرا می‌شود و جایگزین موارد زیر **نیست**:

- چاپ روی پرینتر فیزیکی با درایور و اندازه کاغذ واقعی.
- نصب روی انواع ویندوز و سیاست‌های سازمانی/آنتی‌ویروس و WebView2 متفاوت.
- ارتقای واقعی اطلاعات حساس مشتری از تمامی نسخه‌های قدیمی و بازیابی بکاپ رمزگذاری‌شده در سیستم مشتری.
- پذیرش حسابدار مستقل برای سناریوهای مالیاتی، تسویه، مانده افتتاحیه و اصلاح اسناد.
- کلید عمومی صادرکننده مجوز تجاری و امضای واقعی انتشار.

فقط پس از تکمیل و مستندسازی آن گیت‌ها، فاز ۱ را قابل انتشار عمومی اعلام کنید.

## امنیت و پاک‌سازی

- رمز آزمون، کاربر، شرکت و تراکنش‌ها ساختگی‌اند؛ اطلاعات مشتری دانلود یا بارگذاری نمی‌شوند.
- پروفایل مرورگر برای Windows VM موقت است و اجرای GitHub Actions پس از پایان از بین می‌رود.
- WebView2 debug policy موقت در آزمون تنظیم و پس از تست حذف می‌شود؛ هرگز در build عمومی فعال نمی‌ماند.
- PRها کد و نتیجه آزمون را منتشر می‌کنند، نه فایل نصب عمومی جدید.
