# A02 — شناسایی امن ساختار دیتابیسِ بازیابی‌شده (بدون خواندن اسناد مالی)

**وضعیت:** زیرساخت فنی آزمایشی؛ ابزار انتقال اطلاعات هلو و آداپتور نگاشت نسخه هنوز ساخته نشده‌اند. این ابزار فقط پس از Restore در یک دیتابیس جداگانه کاربرد دارد.

## دلیل

تا وقتی ساختار واقعی دیتابیس هلو شناسایی نشده، نمی‌توان نام جدول اشخاص، اسناد، کالا، فاکتور یا چک را حدس زد. نگاشت حدسی خطرناک است؛ ممکن است اطلاعات به ستون اشتباه بروند یا سند تراز نشود. نسخه واقعی دیتابیس باید با بررسی **metadata فقط‌خواندنی** مشخص شود و در قالب قرارداد نسخه‌دار تأیید گردد.

## قابلیت جدید

اسکریپت scripts/a02-isolated-schema-inventory.ps1 در Windows PowerShell 5.1:

- فقط به نمونه محلی و اختصاصی SQL Server به نام FINORAMIG و دیتابیس با نام FinoraHoloo_<32-hex> متصل می‌شود. نام دیتابیس master، Holoo1، نمونه‌های دلخواه یا سرور راه‌دور رد می‌شوند.
- در تست خودکار فقط جفت اختصاصی FinoraA02_<12-hex> و A02Restore_<همان شناسه> را می‌پذیرد.
- ابتدا آنلاین‌بودن دیتابیس را از sys.databases کنترل می‌کند؛ سپس فقط کاتالوگ‌های سیستمی SQL را می‌خواند.
- حالت Inspect فقط تعداد جدول/ستون، تعداد کلید اصلی/خارجی و اثر انگشت SHA-256 را چاپ می‌کند؛ نام جدول و ستون در خروجی عمومی ظاهر نمی‌شود.
- حالت PrivateManifest فراداده ساختار را می‌خواند: نام جدول/ستون، نوع و اندازه، NULL/Identity/Computed، کلیدهای اصلی، ایندکس‌های یکتا و ارتباط‌های Foreign Key. **هیچ ردیف تجاری، نمونه داده، تعداد ردیف، مبلغ، نام مشتری، شماره سند یا شماره چک خوانده نمی‌شود.**
- فایل خروجی PrivateManifest با Windows DPAPI در محدوده CurrentUser رمز می‌شود. فایل موقت در همان پوشه ایجاد می‌شود و ACL نهایی فقط به کاربر جاری، SYSTEM و گروه محلی Administrators مجوز Full Control می‌دهد. مسیر باید روی دیسک ثابت محلی باشد، والدها Reparse Point نباشند و مقصد از قبل وجود نداشته باشد.
- حالت DecryptManifest فقط با همان حساب ویندوزی که فایل را تولید کرده، DPAPI را باز می‌کند و JSON محلی با ACL محدود می‌سازد. JSON نام جدول و ستون‌ها را آشکار می‌کند؛ قبل از ارسال یا اشتراک‌گذاری، مالک باید آن را بازبینی کند. فایل DPAPI برای حساب/ماشین دیگر قابل رمزگشایی نیست.
- حالت پیش‌فرض Test فقط داده ساختگی تولید می‌کند و SQL را باز نمی‌کند. CI روی دیتابیس واقعاً بازیابی‌شده اما کاملاً ساختگی، هم Inspect و هم چرخه کامل DPAPI، رمزگشایی، کنترل PK و ACL را اجرا می‌کند.

## برای کار با بکاپ واقعی

صرفاً بعد از Restore موفق نسخه خصوصی هلو در نمونه SQL مجزا، مالک/متخصص این دو دستور را روی همان رایانه و با همان حساب ویندوزی اجرا می‌کند. نام دیتابیس در مثال فرضی است و باید نام تولیدشده توسط Restore ایزوله جایگزین شود:

```powershell
powershell.exe -NoProfile -NonInteractive -File .\scripts\a02-isolated-schema-inventory.ps1 -Mode PrivateManifest -InstanceName FINORAMIG -DatabaseName FinoraHoloo_0123456789abcdef0123456789abcdef -OutputPath C:\FinoraPrivate\holoo-schema.dpapi
powershell.exe -NoProfile -NonInteractive -File .\scripts\a02-isolated-schema-inventory.ps1 -Mode DecryptManifest -InputPath C:\FinoraPrivate\holoo-schema.dpapi -OutputPath C:\FinoraPrivate\holoo-schema.private.json
```

پوشه C:\FinoraPrivate باید از قبل وجود داشته باشد؛ ابزار پوشه ایجاد نمی‌کند، فایل موجود را بازنویسی نمی‌کند و مسیر شبکه، دیسک Removable یا مسیر دارای Reparse Point را نمی‌پذیرد. فایل .dpapi رمز‌شده را برای رمزگشایی توسط حساب دیگر ارسال نکنید. فایل .private.json شامل نام جدول‌ها، ستون‌ها و کلیدهاست؛ آن را عمومی یا در GitHub قرار ندهید. فقط پس از بازبینی و اجازه صریح مالک، نسخه مورد تأیید را از مسیر خصوصی در اختیار مهندس نگاشت قرار دهید. فایل بکاپ اصلی هرگز آپلود نمی‌شود.

## محدوده اعتبار

عبور CI ثابت می‌کند ابزار روی یک ساختار SQL ساختگی و بازیابی‌شده کار می‌کند؛ نه اینکه schema واقعی هلو مشخص شده، اسناد درست خوانده شده یا بدهکار/بستانکار و مانده‌ها تطبیق داده شده باشند. گیت `A02 accepted=false` باقی می‌ماند. کنترل مستقل C1/C2/C3 ضروری است و هیچ نسخه عمومی تولید نمی‌شود.
