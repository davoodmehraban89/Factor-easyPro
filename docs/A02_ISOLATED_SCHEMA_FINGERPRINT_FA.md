# A02 — شناسایی امن ساختار دیتابیسِ بازیابی‌شده (بدون خواندن اسناد مالی)

**وضعیت:** زیرساخت فنی آزمایشی؛ ابزار انتقال اطلاعات هلو و آداپتور نگاشت نسخه هنوز ساخته نشده‌اند. این ابزار فقط پس از Restore در یک دیتابیس جداگانه کاربرد دارد.

## دلیل

تا وقتی ساختار واقعی دیتابیس هلو شناسایی نشده، نمی‌توان نام جدول اشخاص، اسناد، کالا، فاکتور یا چک را حدس زد. نگاشت حدسی خطرناک است؛ ممکن است اطلاعات به ستون اشتباه بروند یا سند تراز نشود. نسخه واقعی دیتابیس باید با بررسی **metadata فقط‌خواندنی** مشخص شود و در قالب قرارداد نسخه‌دار تأیید گردد.

## قابلیت جدید

اسکریپت `scripts/a02-isolated-schema-inventory.ps1` در Windows PowerShell 5.1:

- فقط به نمونه **محلی و اختصاصی** SQL Server به نام `FINORAMIG` و دیتابیس با نام `FinoraHoloo_<32-hex>` متصل می‌شود. نام دیتابیس `master`، `Holoo1`، نمونه‌های دلخواه یا سرور راه‌دور رد می‌شوند.
- در محیط **تست خودکار** فقط جفت اختصاصی `FinoraA02_<12-hex>` و `A02Restore_<همان شناسه>` را می‌پذیرد؛ نمی‌توان آن را روی دیتابیس دلخواه اجرا کرد.
- ابتدا از `sys.databases` آنلاین‌بودن دیتابیس را کنترل می‌کند؛ بعد فقط `sys.tables`، `sys.schemas`، `sys.columns` و `sys.types` را می‌خواند.
- هیچ `SELECT` روی جدول‌های مالی، هیچ نام اشخاص/بانک/فاکتور، هیچ تعداد ردیف تجاری، هیچ دستور `UPDATE`، `INSERT`، `DELETE` یا `RESTORE` اجرا نمی‌کند.
- تعداد جدول و ستون و یک **اثر انگشت SHA-256 تکرارپذیر** از تعریف ستون‌ها (شامل نوع، اندازه، ترتیب و قابلیت NULL) را خروجی می‌دهد. نام جدول و ستون در خروجی عمومی چاپ نمی‌شود. اثر انگشت اثبات اصالت داده نیست و بدون نگاشت/بازبینی نمی‌تواند مهاجرت را مجاز کند.
- حالت پیش‌فرض `Test` فقط داده ساختگی تولید می‌کند، بدون اتصال SQL. در CI همان ابزار در حالت `Inspect` نیز بر دیتابیس **واقعاً بازیابی‌شده اما کاملاً ساختگی** اجرا و با انتظار ۱ جدول و ۲ ستون کنترل می‌شود.

## برای کار با بکاپ واقعی

صرفاً بعد از بازیابی موفق نسخه خصوصی هلو در نمونه SQL مجزا، متخصص می‌تواند این دستور را روی **همان رایانه و به‌صورت خصوصی** اجرا کند:

```powershell
powershell.exe -NoProfile -NonInteractive -File .\scripts\a02-isolated-schema-inventory.ps1 -Mode Inspect -InstanceName FINORAMIG -DatabaseName FinoraHoloo_0123456789abcdef0123456789abcdef
```

نام دیتابیس بالا **فرضی** است؛ باید نام تولیدشده توسط Restore ایزوله جایگزین شود. هیچ فایل بکاپ یا خروجی خام نباید در GitHub آپلود شود. خروجی فقط خلاصه و اثر انگشت است. **برای ساخت آداپتور واقعی، استخراج خصوصی جزییات جدول‌ها و کلیدها با ACL محدود و تأیید مستقل مرحله دیگری است.** این ابزار هنوز آن فایل جزئیات را تولید نمی‌کند.

## محدوده اعتبار

عبور CI ثابت می‌کند ابزار روی یک ساختار SQL ساختگی و بازیابی‌شده کار می‌کند؛ نه اینکه schema واقعی هلو مشخص شده، اسناد درست خوانده شده یا بدهکار/بستانکار و مانده‌ها تطبیق داده شده باشند. گیت `A02 accepted=false` باقی می‌ماند. کنترل مستقل C1/C2/C3 ضروری است و هیچ نسخه عمومی تولید نمی‌شود.
