# A02 — موتور اجرای اختیاری بازیابی مستقل SQL Server (نسخه فنی)

**وضعیت:** این قابلیت هنوز «انتقال بکاپ هلو به Factor-easyPro» نیست. یک ابزار **فنی، بدون رابط ویزارد عمومی** برای متخصص روی رایانه ویندوز است. در محیط توسعه این PR نه موتور SQL Server اجرا شده و نه بکاپ واقعی هلو Restore شده است. حالت پیش‌فرض فقط تست ساختگی و بدون هیچ اتصال/نوشتنی است.

## هدف و مدل امنیت

برای مهاجرت بکاپ هلو، ابتدا باید معلوم شود یک **بکاپ کامل و مجزا** قابل خواندن در SQL Server سازگار وجود دارد. سپس می‌توان آن را با نام تصادفی به یک دیتابیس کاملاً جدید بازیابی کرد؛ بدون آنکه نام و فایل فیزیکی دیتابیس اصلی هلو استفاده شود.

اسکریپت `scripts/a02-isolated-sql-restore.ps1` تنها به نمونه **محلی و مشخص** `FINORAMIG` با پروتکل Shared Memory (`lpc:.`)، احراز هویت یکپارچه ویندوز و دیتابیس `master` وصل می‌شود. نام `FINORAMIG` فقط یک **قرارداد اسمی** است، نه گواه اختصاصی‌بودن واقعی نمونه؛ اختصاصی‌بودن و سطح دسترسی SQL باید جداگانه بررسی شوند.

### سه حالت

| حالت | رفتار | اثر روی سیستم |
|---|---|---|
| `-Mode Test` | تست نام‌گذاری، escaping دستورات و رد مسیرهای خطرناک با اطلاعات کاملاً ساختگی | بدون دسترسی به SQL، بدون فایل، بدون نوشتن |
| `-Mode Inspect` | با فرض داشتن بکاپ استخراج‌شده، `RESTORE HEADERONLY`، `FILELISTONLY` و `VERIFYONLY`، کنترل نسخه/فایل‌های مقصد | بدون ایجاد دیتابیس؛ نیازمند نمونه SQL موجود |
| `-Mode Restore` | پس از کنترل‌ها و دریافت عبارت تأیید مستقل، `RESTORE DATABASE` در **یک دیتابیس با نام جدید و تصادفی**؛ سپس تنها شمارش جداول/ستون‌های ساختار | **دیتابیس جدید روی دیسک ایجاد می‌کند**؛ هیچ سند مالی به Factor-easyPro منتقل نمی‌کند |

### شروط توقف

- Windows PowerShell 5.1 و **نمونه ازقبل آماده‌شده و مستقل** `FINORAMIG`؛ نه نصب موتور SQL، نه روشن‌کردن TCP، نه اتصال به سرور بیرونی
- بکاپ فایل محلی با مسیر مطلق روی درایو محلی، اندازه محدود، بدون symlink/junction در مسیر والد یا خود فایل؛ ZIP اولیه باید **به شکل امن روی نسخه کپی** استخراج شود
- تأیید نسخه موتور و نسخه پشتیبان، backup set یگانه از نوع **FULL DATABASE**، عدم گزارش خرابی سربرگ و وجود فایل‌های داده و لاگ
- حداکثر ۱۶ فایل در `FILELISTONLY`، فقط انواع D و L، نام منطقی یکتا؛ طرح برای FILESTREAM و قالب‌های خاص پشتیبانی نشده و بسته می‌شود
- محل فایل‌های مقصد از پیش‌فرض‌های **خود موتور SQL Server** گرفته می‌شود؛ برای هر فایل نام تازه شامل شناسه تصادفی ۱۲۸ بیتی ساخته می‌شود
- کنترل نبود دیتابیس و فایل مقصد، کنترل نبود مسیر در `sys.master_files` و فضای آزاد حداقل حجم فایل‌ها **به‌علاوه دو گیگابایت** برای هر درایو؛ سپس `VERIFYONLY WITH MOVE`
- حالت Restore تنها با عبارت دقیق `I_AUTHORIZE_A_NEW_ISOLATED_SQL_DATABASE` فعال می‌شود. هیچ `WITH REPLACE`، `DROP DATABASE`، `ALTER DATABASE` یا واردسازی مالی در مسیر برنامه وجود ندارد.
- قبل از Restore کنترل برخورد نام/مسیر یک بار دیگر انجام می‌شود. با این حال کنترل‌های نرم‌افزاری به‌تنهایی **انحصار واقعی نمونه SQL یا حذف کامل شرایط مسابقه (TOCTOU)** را اثبات نمی‌کنند.
- SHA-256 محتوای بکاپ (بدون انتشار/چاپ هش) پیش از بررسی SQL ثبت و پس از VERIFYONLY و بلافاصله پیش از RESTORE دوباره محاسبه می‌شود تا جابه‌جایی فایل در این فاصله متوقف شود؛ همچنان قفل انحصاری سیستم‌فایل نیست.
- بعد از RESTORE، وضعیت دیتابیس جدید در `sys.databases` باید `ONLINE` باشد؛ این تنها یک کنترل عملیاتی است و **جایگزین DBCC CHECKDB یا تطبیق حسابداری مستقل نیست**.

## دستور نمونه (صرفاً برای متخصص و محیط آزمایشی)

```powershell
# آزمون ساختگی و بدون دسترسی به داده
powershell.exe -NoProfile -NonInteractive -File .\scripts\a02-isolated-sql-restore.ps1 -Mode Test

# پیش‌بررسی پس از نصب نمونه مجزای SQL و استخراج امن بکاپ
powershell.exe -NoProfile -NonInteractive -File .\scripts\a02-isolated-sql-restore.ps1 -Mode Inspect -BackupPath 'D:\Private\HolooCopy.bak'

# اجرای اختیاری که پایگاه داده جدید ایجاد می‌کند؛ فقط در محیط اختصاصی:
powershell.exe -NoProfile -NonInteractive -File .\scripts\a02-isolated-sql-restore.ps1 -Mode Restore -BackupPath 'D:\Private\HolooCopy.bak' -ConsentPhrase 'I_AUTHORIZE_A_NEW_ISOLATED_SQL_DATABASE'
```

**هشدار:** دستور سوم نباید روی رایانه مشتری یا محیط اصلی هلو بدون صلاحیت/آزمون و تأیید مستقل اجرا شود؛ عبارت تأیید مانع خطای انسانی نیست.

### پس از بازیابی

- خروجی شامل نام دیتابیس جدید (برای تشخیص آن روی همان رایانه) و **تعداد جدول‌ها و ستون‌ها** است؛ عمداً ردیف‌های مالی، نام مشتری، شماره چک و مسیر فایل در خروجی نیست.
- این خروجی فقط مرحله استخراج ساختار را آماده می‌کند. صحت اسناد و مبالغ، نگاشت نسخه واقعی هلو، واحد ریال/تومان، شماره‌گذاری، انتقال به IndexedDB، بکاپ مقصد و rollback هنوز جداگانه باید ساخته و آزموده شوند.
- اگر حین Restore خطا رخ دهد، یک دیتابیس **نیمه‌کاره با نام جدید ممکن است باقی بماند**. اسکریپت برای جلوگیری از حذف ناخواسته، هیچ پاکسازی یا حذف دیتابیس را خودکار اجرا نمی‌کند. بررسی و پاکسازی محیط آزمایش باید تحت اختیار متخصص انجام شود.
- تمام بررسی‌های عمومی CI فقط با داده‌های ساختگی و حالت Test است؛ **SQL Server واقعی و بکاپ صاحب‌داده به GitHub/CI ارسال نمی‌شوند**.

## گیت‌های انتشار

- آزمون Windows PowerShell 5.1 در CI با حالت Test، ساخت installer و آزمون native برای تغییرات مرتبط
- آزمایش REAL روی نمونه SQL مستقل در ماشین مجازی خصوصی با همان بکاپ مجاز مالک، بررسی سازگاری نسخه و فضای دیسک، و اثبات recovery
- تأیید مستقل کنترل مالی C1، امنیت C2، نصب/بازیابی ویندوز C3
- وضعیت `A02 accepted: false` تا پایان همه مراحل؛ **هیچ ادعای انتقال یک‌کلیکی یا Restore موفق واقعی مجاز نیست.**
