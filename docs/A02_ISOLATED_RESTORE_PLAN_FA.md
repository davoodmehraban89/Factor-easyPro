# A02 — طرح ایزوله و بدون اجرای RESTORE دیتابیس هلو

**وضعیت:** این ماژول **فقط تولیدکنندهٔ طرح** است. هیچ ارتباط SQL، نصب پیش‌نیاز، ایجاد فایل، بازیابی دیتابیس یا ثبت سند انجام نمی‌دهد. «طرح تولید شد» نباید به‌عنوان «بکاپ بازیابی شد» گزارش شود.

## ورودی و خروجی

`src/core/HolooIsolatedRestorePlan.mjs` پنج ورودی کنترل‌شده می‌گیرد: `backupFile` مسیر فایل *از پیش استخراج‌شده و تأییدشده* .bak؛ `sqlDataDirectory` مسیر محلی معتبر و تحت کنترل SQL Server برای فایل‌های پایگاه داده؛ `restoreToken` یک شناسه تصادفی ۳۲ نویسهٔ hex تولیدشده توسط مولد امن؛ `backupSetPosition=1`؛ و `files` شامل نام منطقی، نوع `D/L` و اندازه هر فایل از `RESTORE FILELISTONLY` که قبلاً روی نمونه خصوصی SQL Server تأیید شده است.

ماژول دو دستور **فقط به‌صورت رشته برای تأیید آتی** تولید می‌کند:

- `RESTORE VERIFYONLY ... WITH FILE=1, MOVE ...` — بررسی هدف و امکان بازگردانی بدون اجرای Restore.
- `IF DB_ID(N'FinoraHoloo_<token>') IS NOT NULL THROW ...; RESTORE DATABASE [FinoraHoloo_<token>] ... MOVE ... RECOVERY` — طرح نظری بازیابی به نام اختصاصی جدید، با انتقال **همه فایل‌های D/L** به نام‌های خنثی و مجزا.

این دستورات **خودکار اجرا نمی‌شوند**. در طرح هیچ `WITH REPLACE`، `DROP DATABASE` یا تغییر دیتابیس موجود وجود ندارد. فایل‌های مقصد با نام‌های دارای شناسه تصادفی تولید می‌شوند، و برای همهٔ فایل‌ها `MOVE` اجباری است.

## شرایط توقف عمدی

- مسیرهای شبکه‌ای/UNC، مسیر نسبی، Path Traversal، ADS، نام مشکوک و نوع ناشناخته FILESTREAM رد می‌شوند.
- چند backup set در این نسخه پشتیبانی نمی‌شود؛ باید به‌صورت شفاف مشخص شود.
- نبود فایل data یا log، نام منطقی تکراری، بیش از ۱۶ فایل یا اندازه غیرصحیح رد می‌شود.
- SQL و نام فایل‌ها با escaping کامل رشته Unicode ساخته می‌شوند و مقدار غیرقابل‌چاپ پذیرفته نیست.
- هر طرح همچنان صراحتاً `canImport=false` و `restoreExecuted=false` دارد.

## محدودیت‌های پذیرش

**پیش از اجرای واقعی** باید عامل اجرایی *مستقل از این ماژول* موارد زیر را بررسی و اثبات کند:

۱. نمونه SQL فقط محلی، اختصاصی و با سطح دسترسی محدود است؛ از نمونه اصلی هلو یا سرور عملیاتی استفاده نمی‌شود.
۲. فایل ZIP به‌صورت امن به نسخه جداگانه استخراج شده و CRC و هش کپی تأیید شده است.
۳. سازگاری نسخه بکاپ با موتور، `HEADERONLY`، `FILELISTONLY`، `VERIFYONLY WITH MOVE` و فضای آزاد کافی تأیید شده‌اند.
۴. **قبل و لحظه اجرای RESTORE** نام دیتابیس و همهٔ مسیرهای مقصد فاقد فایل/دیتابیس موجودند؛ سیاست شکست و پاکسازی تأییدشده و قابل گزارش است.
۵. مالک قبل از ایجاد دیتابیس رضایت روشن می‌دهد؛ هیچ تأیید امنیتی ویندوز پنهان یا دور زده نمی‌شود.
۶. بعد از restore واقعی، خروجی schema-only خصوصی و نسخه واقعی جداول برای آداپتور هلو بررسی می‌شود و حسابدار مستقل مانده‌ها/تراز، اشخاص، انبار، چک، فاکتور و اسناد را کنترل می‌کند.
