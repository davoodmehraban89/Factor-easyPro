# گزارش ممیزی Runtime و Schema هلو — ۱۴۰۵/۰۸/۲۰

**وضعیت:** برداشت فقط‌خواندنی؛ شواهد محلی، بدون تغییر دیتابیس  
**محیط:** دستگاه Aram، نصب `H:\\Holoo`، دیتابیس مرجع `Holoo1` روی `ARAM\\TNC`  
**هدف:** شناخت runtime، ساختار داده، وابستگی‌های ایستا و مسیر ارتقای دیتابیس برای تصمیم‌های Factor-easyPro  
**محدودیت:** این گزارش اثبات‌کننده parity رفتاری نیست و هیچ مجوزی برای کپی/توزیع فایل‌های اختصاصی هلو ایجاد نمی‌کند.

## 1. جمع‌بندی اجرایی

1. فایل اجرایی نصب‌شده `Holoo.exe` نسخه فایل `9.2.5.0` و محصول `Holoo` از `Torfeh Negar.Co` است؛ فایل `Write.txt` در کنار آن Version `9.25` را ثبت کرده است. این دو نمایش نسخه را باید به‌عنوان metadataهای متفاوت (FileVersion در برابر برچسب داخلی) نگه داشت، نه اینکه یکی را جایگزین دیگری کنیم.
2. فایل `Holoo_dataSource.txt` نام Instance را `Aram\\TNC` اعلام می‌کند. دیتابیس `Holoo1` در همین Instance آنلاین و روی موتور SQL Server `10.50.4000.0` (SQL Server 2008 R2 SP2 Express 64-bit) با compatibility level برابر 80 است.
3. در `Holoo1` تعداد 334 جدول کاربری، 25 View، 179 Stored Procedure کاربری، 35 Function و یک DML Trigger کاربری وجود دارد. شمارش 210 در `sys.procedures` شامل 31 رویه system-shipped است؛ عدد درست برای رویه‌های متعلق به برنامه 179 است.
4. 253 کلید اصلی، 2 قید Unique، 874 Default Constraint و صفر Foreign Key و صفر Check Constraint ثبت شده‌اند. بنابراین رابطه‌های دامنه‌ای عمدتاً باید از روی کلیدهای ترکیبی، کدهای مشترک و منطق برنامه کشف شوند.
5. کاتالوگ وابستگی SQL، 452 ارجاع ایستا را در 182 ماژول نشان می‌دهد. این عدد کامل نیست: SQL پویا، نام جدول‌های ساخته‌شده در runtime و بعضی وابستگی‌های غیرقابل تحلیل ایستا در آن دیده نمی‌شوند.
6. اسکریپت‌های `SV_Scrp.sql` و `T_Scrp.sql` بزرگ و batch-based هستند. اجرای مستقیم آن‌ها روی دیتابیس واقعی یا clone بدون شناخت کامل DBTools، baseline و markerهای نسخه ممنوع است.

### پیامد برای طراحی Factor-easyPro

- شناسه ردیف سند باید در محدوده سند یکتا باشد؛ صرفاً شماره ردیف سراسری یا ترتیب نمایشی کافی نیست.
- نوع فاکتور بخشی از کلید است؛ حذف آن از کلید/ارجاع می‌تواند فاکتورهای هم‌شماره با انواع متفاوت را مخلوط کند.
- کلید حساب کل/معین/تفصیلی در هلو مرکب است؛ تبدیل آن به شناسه داخلی مستقل در مدل جدید قابل قبول است، به شرط نگهداری mapping برگشت‌پذیر.
- رابطه‌های سند، فاکتور، موجودی و خزانه باید در مدل جدید با Foreign Key و transaction اتمی صریح شوند؛ نبود FK در هلو نباید به معماری جدید منتقل شود.
- مقادیر مالی در schema قدیمی عمدتاً `float` هستند. مدل جدید برای پول باید از integer در واحد پایه یا DECIMAL با scale کنترل‌شده استفاده کند؛ تبدیل باید نسخه‌دار و قابل تطبیق باشد.

## 10. گام بعدی و معیار خروج

1. شناسایی دقیق ساختار و markerهای پیشرفت در `MSETUP2` و هر جدول version/setup مرتبط، فقط با خواندن نام ستون‌ها و بدون انتشار مقادیر حساس.
2. تحلیل کامل تعریف و پارامترهای رویه‌های هسته سند، فاکتور، مانده و چک؛ تهیه ماتریس read/write برای هر جدول.
3. بررسی viewها و توابع کاردکس، به‌خصوص `W_ArtKardex*` و `sp_ReturnArtExistWithKardex1`.
4. آماده‌سازی سناریوهای مصنوعی برای trace برنامه: ایجاد سند، خرید، ورود موجودی، فروش، دریافت/پرداخت، چک و برگشت.
5. اجرای Holoo فقط روی clone آزمایشگاهی و ثبت trace؛ هرگز روی دیتابیس واقعی.
6. تبدیل یافته‌ها به قرارداد migration و تست parity برای Factor-easyPro؛ نه کپی کورکورانه stored procedureهای هلو.

**معیار پایان این مرحله:** data dictionary، کلیدها، dependency inventory و ریسک‌های نسخه‌گذاری مستند و قابل بازبینی شده‌اند. هنوز parity اجرایی، installer، migration یا مجوز توزیع Runtime تأیید نشده است.

## 12. تطبیق markerهای ارتقای دیتابیس با MSETUP2

نام ستون‌های `MSETUP2` نشان می‌دهد تنظیمات کلیدی به‌صورت key/value نگهداری می‌شوند. فقط نام کلیدهای مرتبط و سه مقدار نسخه/پیشرفت زیر خوانده شدند؛ سایر مقادیر تنظیمات خوانده یا صادر نشدند.

| دیتابیس | DBVersion (Integer) | Run_TableScript_Count | Run_ViewScript_Count |
|---|---:|---:|---:|
| `Holoo1` | 4 | 537 | 474 |
| `Holoo1_FACTORLAB_20261110` | 4 | 537 | 474 |

تطبیق با Header فایل‌ها:
- `T_Scrp.sql`: مقدار `MAX_GO_NO=537` و `Run_TableScript_Count=537`.
- `SV_Scrp.sql`: مقدار `MAX_GO_NO=474` و `Run_ViewScript_Count=474`.

این تطبیق، فرض قبلی درباره وجود checkpointهای جداگانه برای اسکریپت‌های جدول و View را تقویت و به شواهد مستقیم تبدیل می‌کند. هر دو دیتابیس از نظر این سه marker در یک نقطه گزارش‌شده قرار دارند. بااین‌حال، مقدار برابر marker به‌تنهایی ثابت نمی‌کند DBTools بدون خطا همه batchها را اجرا کرده یا وضعیت فایل‌های جانبی و داده‌ها سالم است؛ برای اثبات آن باید منطق DBTools، logها و رفتار rollback در clone بررسی شود.

**گام بعدی دقیق:** بدون اجرای DBTools، فقط مسیرهای خواندن/نوشتن آن، نام کلیدهای MSETUP2 و ترتیب پردازش `GO_NO`ها را با تحلیل ایستا/trace روی clone شناسایی کنیم. اجرای migration همچنان ممنوع است تا baseline و rollback قابل اثبات شوند.

## 13. اثرانگشت فایل‌های اجرایی و وضعیت امضا

برای ثبت هویت دقیق فایل‌های محلی، SHA-256 پنج فایل اصلی محاسبه و وضعیت Authenticode بررسی شد. همه پنج فایل در محیط فعلی `NotSigned` گزارش شدند:

- `Holoo.exe`
- `DBTools.exe`
- `Setup.exe`
- `TNCServices.exe`
- `Convertor.exe`

هش کامل، اندازه و metadata نسخه در `holoo_runtime_binary_fingerprints.csv` ثبت شده است.

**برداشت امنیتی:** unsigned بودن به‌تنهایی اثبات بدافزار یا دستکاری نیست، اما اصالت ناشر و یکپارچگی فایل را نیز تأیید نمی‌کند. این هش‌ها فقط fingerprint محلی‌اند و با هش رسمی ناشر تطبیق داده نشده‌اند. بنابراین این فایل‌ها نباید در Installer عمومی Factor-easyPro بسته‌بندی یا به‌روزرسانی خودکار شوند، مگر اینکه مجوز کتبی، منبع رسمی، هش مرجع و بررسی امنیتی مستقل فراهم شود.

## 14. شواهد ایستای DBTools

بدون اجرای `DBTools.exe`، رشته‌های متنی قابل‌خواندن داخل فایل با جست‌وجوی محدود و هدفمند بررسی شدند. رشته‌های زیر در binary دیده شدند:

- `TableMSetup2`
- `Run_TableScript_Count`
- `Run_ViewScript_Count`
- `Scripts\\T_Scrp.sql`
- `Scripts\\SV_Scrp.sql`
- `[GO_NO]=`
- `sql.txt`
- `AUTO_UPDATE`

این شواهد با یافته‌های مستقیم `MSETUP2` و Header اسکریپت‌ها سازگار است: DBTools احتمالاً checkpointهای مستقل اسکریپت جدول و View را می‌خواند و batchها را با markerهای `GO_NO` مدیریت می‌کند. واژه «احتمالاً» مهم است؛ رشته‌های binary به‌تنهایی ترتیب اجرای واقعی، transaction boundary، rollback یا الگوریتم retry را ثابت نمی‌کنند.

همچنین رشته‌های مربوط به OLE DB و الگوهای اتصال Windows Integrated Security و SQL Authentication در فایل دیده شدند؛ هیچ مقدار credential استخراج یا در گزارش ثبت نشده است.

**محدودیت:** چون فایل unsigned است و اصالت ناشر/هش رسمی در دسترس نیست، DBTools اجرا نشده است. مرحله بعد تحلیل ایستای بیشتر یا trace فقط در clone ایزوله و پس از ثبت snapshot و روش بازگشت خواهد بود.

## 15. وضعیت اجرای زنده و محدودیت Trace

در بررسی وضعیت جاری سیستم، دو process از `Holoo.exe` در حال اجرا بودند. در فهرست sessionهای SQL Server، یک session برنامه Holoo به دیتابیس `Holoo1` متصل بود؛ برای `Holoo1_FACTORLAB_20261110` session برنامه‌ای مشاهده نشد. ابزار SQL Server Profiler نیز در مسیرهای استاندارد SQL Server 2008 R2 نصب‌شده پیدا نشد؛ `SQLDiag.exe` موجود است، اما برای این ممیزی اجرا نشد.

**تصمیم ایمنی:** هیچ Trace، SQL Profiler، تغییر connection، اجرای برنامه، ثبت فاکتور آزمایشی یا عملیات UI روی محیط جاری انجام نشد؛ زیرا برنامه در حال استفاده از دیتابیس `Holoo1` بود و مالکیت/ماهیت داده‌های آن را نباید فرض کرد. این محدودیت آگاهانه است، نه نقص در اجرای ممیزی.

برای مرحله رفتاری باید ابتدا یک محیط ایزوله با دیتابیس clone، حساب کاربری آزمایشی و داده مصنوعی آماده شود. تا قبل از آن، عملیات روی `Holoo1` ممنوع است.
