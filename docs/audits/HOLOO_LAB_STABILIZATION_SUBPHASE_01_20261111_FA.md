# گزارش تثبیت آزمایشگاه هلو — زیرمرحله اجرایی اولویت‌دار ۱

**تاریخ اجرا:** ۱۴۰۵/۰۸/۲۰ — 2026-11-11
**وضعیت:** بخش حفاظت و تثبیت مرجع انجام شد؛ محیط اجرای رفتاریِ مستقل هنوز آماده پذیرش نیست.
**دامنه:** آماده‌سازی محیط امن برای مهندسی معکوس رفتاری هلو؛ این زیرمرحله ذیل فاز ۰ کتابچه ده‌فازی FINORA قرار می‌گیرد و جایگزین فاز ۱ رسمی «هسته معماری، داده و شرکت‌ها» نیست.

## 1. تصمیم اجرایی

هدف این مرحله این بود که پیش از هر Trace یا عملیات حسابداری، مرجع واقعی هلو از محیط آزمایش جدا، نسخه پشتیبان آن قابل‌اعتبارسنجی، و Clone هم‌ساختار فعلی به‌صورت غیرقابل‌نوشتن نگهداری شود.

**نتیجه:** مرجع ساختاری فعلی با اطمینان شناسایی و یک نسخه پشتیبان مستقل و معتبر از Clone گرفته شد. Clone هم‌ساختار فعلی به حالت READ_ONLY منتقل شد. هیچ DDL/DML یا عملیات UI روی دیتابیس عملیاتی Holoo1 و Holoo6 انجام نشد.

با این حال، هنوز یک دیتابیس کاریِ هم‌ساختار، قابل‌نوشتن، واقعاً ایزوله و دارای داده مصنوعی نداریم. بنابراین Trace، ثبت فاکتور آزمایشی و آزمون رفتاری در این مرحله مجاز/انجام‌شده محسوب نمی‌شوند.

- تصمیم: این Instance و دو دیتابیس عملیاتی خارج از دامنه آزمایش باقی می‌مانند.

## 3. نسخه پشتیبان طلایی و کنترل بازیابی

Backup موجود Clone هم‌ساختار از مسیر محلی منبع به یک پوشه مستقل و با ACL محدود کپی شد.

- مسیر محلی: C:\FINORA-SQL-Lab\backups\Holoo1_FACTORLAB_20261110_GOLDEN_20261111.bak
- اندازه: 260,919,296 bytes
- SHA-256: B4029F76B53B607FE075416E1949A0EF55FDD0237E7280EF66C63B1C0F93C50B
- Hash فایل مقصد با فایل مبدأ برابر بود.
- RESTORE VERIFYONLY WITH CHECKSUM موفق شد؛ SQL Server پیام «The backup set on file 1 is valid» برگرداند.
- RESTORE HEADERONLY، نام دیتابیس مبدأ را Holoo1، نسخه دیتابیس را 661 و زمان پایان Backup را 2026-11-10 18:04:12 ثبت کرد.
- RESTORE FILELISTONLY دو فایل منطقی Holoo_Data و Holoo_Log را شناسایی کرد.
- DBCC CHECKDB روی Holoo1_FACTORLAB_20261110 پیش و پس از تغییر READ_ONLY، بدون خطا و با Exit Code صفر تمام شد.

**حفاظت فایل:** ACL پوشه backups از ارث‌بری خارج و به این Principalها محدود شد: SYSTEM با Full Control، Administrators با Full Control، NETWORK SERVICE با Modify و ARAM\Davood با Modify. هیچ فایل Backup یا داده عملیاتی به GitHub منتقل نشده است.

## 4. تغییر کنترل‌شده انجام‌شده

پس از تأیید صفر بودن نشست‌های دیتابیس Clone و موفقیت Verify Backup:

- فقط دیتابیس Holoo1_FACTORLAB_20261110 به READ_ONLY تغییر کرد.
- وضعیت نهایی آن ONLINE / MULTI_USER / READ_ONLY است.
- وضعیت Holoo1 همچنان ONLINE / MULTI_USER / READ_WRITE باقی ماند.
- وضعیت Holoo6 تغییر نکرد.
- روی دیتابیس‌های عملیاتی هیچ دستور DDL، DML، Restore، Migration یا DBTools اجرا نشد.

این تغییر قابل برگشت است، اما تا زمان ایجاد Working Copy مستقل، Clone طلایی باید READ_ONLY باقی بماند.

## 5. کنترل ایزولاسیون و ریسک‌های باقی‌مانده

- در زمان بررسی، برای پردازش‌های SQL Server Listener TCP روی پورت‌های بررسی‌شده مشاهده نشد و اتصال TCP محلی به Instance پیش‌فرض رد شد.
- Endpointهای TSQL Named Pipes در Instance پیش‌فرض STARTED بودند؛ بنابراین ادعای «ایزولاسیون کامل شبکه» مجاز نیست.
- Instance هلو و Clone هم‌ساختار روی یک Host و یک Instance مشترک TNC قرار دارند؛ READ_ONLY بودن Clone، جداسازی زیرساختی کامل ایجاد نمی‌کند.
- در Instance پیش‌فرض Login گروه BUILTIN\Users مشاهده شد. مجوز مؤثر همه مسیرهای اتصال و Named Pipes هنوز ممیزی کامل نشده است.
- ACL ریشه C:\FINORA-SQL-Lab همچنان از Parent مجوزهای گسترده‌تری به ارث می‌برد؛ فقط زیرپوشه backups با ACL مستقل سخت‌سازی شد.
- این موارد باید پیش از اجرای Runtime در فاز بعد بسته شوند.

### 5.1. مسیر اتصال Runtime و فهرست شرکت‌ها

- فایل H:\\Holoo\\Holoo_dataSource.txt مقدار Instance برابر ARAM\\TNC را ثبت می‌کند.
- در master همان Instance، جدول dbo.Alias_Holoo وجود دارد؛ 7 ستون دارد، کلید اصلی آن aliasID است و Trigger ثبت‌شده‌ای ندارد.
- جدول Alias_Holoo ده Alias دارد؛ فقط دو Alias به دیتابیس ONLINE متصل‌اند و هشت Alias دیگر در حال حاضر دیتابیس متناظر ندارند.
- Clone طلایی در Alias_Holoo ثبت نشده است؛ بنابراین در فهرست عادی شرکت‌های Runtime ظاهر نمی‌شود.
- در master Instance پیش‌فرض، جدول Alias_Holoo وجود ندارد. پس تغییر ساده Holoo_dataSource.txt از TNC به Instance پیش‌فرض، راه‌اندازی مستقل Runtime را کامل نمی‌کند.
- فایل DefAlias.dat فقط 2 بایت است؛ SHA-256 آن C6F3AC57944A531490CD39902D0F777715FD005EFAC9A30622D5F5205E7F6894 ثبت شد، اما معنای بایت‌ها هنوز رمزگشایی/اثبات نشده است.
- جست‌وجوی کلیدهای اتصال در فایل‌های متنی config/ini/xml نتیجه دیگری نداد؛ این بررسی، وجود تنظیمات در Registry یا Binary را رد نمی‌کند.

**نتیجه ایمنی:** برای نمایش Clone به Runtime فعلی نباید Alias_Holoo روی Instance عملیاتی تغییر کند؛ این کار فهرست شرکت‌های نرم‌افزار اصلی را تغییر می‌دهد. Runtime مستقل به یک Alias Catalog مستقل یا Instance جداگانه نیاز دارد.

### 5.2. امکان نصب Instance مستقل

- فایل Bootstrap موجود SQL Server 2008 R2 نسخه 10.50.4000.0 دارد؛ امضای Authenticode آن معتبر گزارش شد و SHA-256 برابر 041B2E423A8FE5B67C3F09C8C9E9E58C1958C6E44912A385A65F78FA1E7D714C است.
- اندازه خود Bootstrap فقط 171,976 بایت و مجموع پوشه Setup Bootstrap حدود 26,969,675 بایت است.
- در مسیرهای محلی بررسی‌شده، رسانه کامل نصب SQLEXPR یا SQL Server 2008 R2 پیدا نشد؛ Bootstrap به‌تنهایی اثبات‌کننده وجود Media کامل نیست.
- [Microsoft Download Center](https://www.microsoft.com/en-ie/download/details.aspx?id=30438) هنوز SQL Server 2008 R2 SP2 Express نسخه 10.50.4000.0 را فهرست می‌کند؛ اما سیستم‌عامل‌های فهرست‌شده شامل Windows 11 نیستند.
- طبق [Microsoft Lifecycle](https://learn.microsoft.com/en-us/lifecycle/products/microsoft-sql-server-2008-r2)، پشتیبانی Extended این محصول در 2019-07-10 پایان یافته است.
- Instance جدید نصب نشد و فایل دانلودی نیز دریافت/اعتبارسنجی نشد. اجرای موتور EOL روی Windows 11 بدون VM/ایزولاسیون و رضایت صریح مالک توصیه نمی‌شود. طبق ADR-003، نصب به Media رسمی امضاشده، بررسی Hash/ناشر، نمایش EULA و رضایت صریح نیاز دارد.

## 6. چرا هنوز Trace را شروع نمی‌کنیم؟

سه نامزد موجود، هیچ‌کدام به‌تنهایی Working Lab تأییدشده نیستند:

1. Holoo1_FACTORLAB_20261110 از نظر Schema دقیقاً با مرجع فعلی برابر است، اما داده عملیاتی واقعی دارد و روی همان Instance هلو قرار دارد؛ اکنون فقط مرجع READ_ONLY است.
2. FINORA_HOLOO_LAB_20261111 داده عملیاتی واقعی دارد و Schema آن 16 اختلاف ستون، 2 اختلاف ماژول و 4 اختلاف Constraint با مرجع فعلی دارد.
3. HolooTemplate_LAB_20261110 و HolooUpgrade_LAB_20261110 فقط 106 جدول دارند و وضعیت Seed آن‌ها هنوز برای ساخت شرکت مصنوعی تأیید نشده است.

**شرط شروع Trace:** یک Runtime آزمایشگاهی مستقل با دیتابیس هم‌ساختار نسخه فعلی، داده مصنوعی/ناشناس‌سازی‌شده، حساب آزمایشی محدود، Backup/Restore تأییدشده و مسیر اتصال مستقل از Holoo1 ساخته شود. تا آن زمان، هیچ ثبت فاکتور، سند، دریافت/پرداخت یا تغییر تنظیمات در هلو اجرا نمی‌شود.

| شناسایی Instanceها و دیتابیس‌های عملیاتی/آزمایشگاهی | انجام شد |
| اثبات Schema Parity برای Clone فعلی | انجام شد |
| DBCC CHECKDB روی Clone و Templateها | انجام شد |
| Backup مستقل با Hash و Verify | انجام شد |
| READ_ONLY کردن Clone طلایی | انجام شد |

**تصمیم وضعیت:** زیرمرحله از نظر حفاظت مرجع و آماده‌سازی شواهد تکمیل شده، اما گیت «آمادگی اجرای رفتاری» هنوز BLOCKED است. درصد پیشرفت اعلام نمی‌شود؛ زیرا معیارهای حیاتی محیط مستقل هنوز پاس نشده‌اند.

## 8. اقدام بعدی اولویت‌دار

1. تحلیل read-only ساختار اتصال Holoo، Alias_Holoo، Holoo_dataSource و روش انتخاب دیتابیس، بدون تغییر تنظیمات محیط جاری.
2. طراحی محیط Runtime مستقل و محلی که به Instance عملیاتی TNC متصل نشود.
3. بررسی مجاز بودن استفاده از DBTools و طراحی مسیر ساخت دیتابیس هم‌ساختار از Template/Backup، فقط روی کپی آزمایشگاهی.
4. ساخت Working DB با داده مصنوعی؛ حذف/ناشناس‌سازی داده واقعی باید پیش از هر استفاده رفتاری اثبات شود.
5. آزمون اتصال و سپس اجرای سناریوی اول «سند حسابداری مصنوعی» با ثبت قبل/بعد metadata و row-countهای مجاز.

## 9. محدودیت و حریم داده

این سند فقط نام دیتابیس‌ها، شمارش ساختاری، وضعیت‌ها، مسیر و Hash فایل Backup را ثبت می‌کند. هیچ نام مشتری، مبلغ، شماره حساب، شماره چک، رمز، محتوای ردیف عملیاتی، فایل Backup یا Binary اختصاصی در مخزن قرار نگرفته است.
